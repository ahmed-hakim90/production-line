# الدفعة الثانية — لوحات العمل والإنتاج

## النطاق المسلّم محليًا — ٢٠٢٦-٠٩-٠٨

هذه الدفعة تربط أساس الخادم في ADR-014 بالتطبيق الفعلي. ليست صفحة HTML مستقلة، ولا تفعّل الجودة أو المخزن قبل دفعاتهما. تفعيل الواجهات والإجراءات الجديدة محصور في `dev:lab` ومحاكيات مشروع تجريبي؛ لم يحدث نشر أو تعديل للبيانات الإنتاجية.

### ماذا يفعل المستخدم؟

1. **مدير الإنتاج:** يجد «مهامي في أوامر الشغل» في الصفحة الرئيسية، يختار «تجهيز أمر شغل»، يحدد المنتج والخط والمشرف والكمية والأيام وأوقات العمل والراحة. تظهر معاينة الساعات وأهدافها، ثم يحفظ التجهيز ويفتح صفحة الأمر لاعتماده بشكل مستقل.
2. **مشرف الإنتاج:** يجد الأمر المعتمد ضمن مهامه حسب تكليفه، يفتح الساعة مباشرة، يختار العمالة الفعلية ويحفظها ثم يبدأ الساعة. يحفظ الخادم هويات العمال وأسماءهم وعددهم. يسجل الإنتاج والمرفوض المبدئي والملاحظات، أو يتوقف بسبب ثم يستأنف.
3. **بطاقة الحاوية:** بعد تسجيل الإنتاج، يستطيع المشرف معاينة وطباعة بطاقة إنتاج منفصلة عن تقرير الجودة. البطاقة تحتوي QR ورقم المستند والحاوية والأمر والمنتج والخط والوقت والكميات والعمالة. إعادة الطباعة لا تُنشئ حركة أو حاوية جديدة.
4. **مدير الجودة:** يفتح الأمر ويكلف عدة مراقبين بالخط. مصدر التكليف هو سجل الخط، وليس نسخة قديمة في أمر آخر.
5. **المراقب المكلف:** يرى حاويات الخط المنتظرة، ويستطيع فتح رابط البطاقة لنفس الساعة. تظهر رسالة صريحة أن الفحص واعتماد تقريره غير مفعّلين بعد؛ لا أزرار اعتماد أو قبول وهمية.
6. **مشرف التغليف:** لوحته تعرض عدم وجود مهام استلام مفعلة بعد. لا توجد وسيلة لاستلام الإنتاج غير المعتمد.

«مهامي» موجودة في مدخل الصفحة الرئيسية لكل دور، وأيضًا في مسار لوحة المشرف المباشر. قائمة `/work-orders` داخل المختبر تعرض الأوامر الجديدة المتاحة للمستخدم. صفحة تفاصيل الأمر تبقى `/work-orders/:id`، وتتعرف على الإصدار الجديد؛ روابط المهام والبطاقات تحدد الساعة والمستند في query parameters.

## القرارات التقنية

- القراءة عبر `getWorkOrderCycleWorkspace` تتحقق من النشاط والشركة والدور والتكليف على الخادم. لا تعتمد على إخفاء البطاقات في الواجهة.
- الدليل المستخدم للاختيار لا يعيد رواتب أو بيانات اعتماد: هويات وأسماء فقط، وللدور المناسب.
- كل الإجراءات عبر `mutateWorkOrderCycle` الموجود؛ لم تُضف كتابة Firestore من الصفحات.
- التحديث كل ١٥ ثانية وعند استعادة التركيز/الاتصال. عند انقطاع الاتصال تبقى البيانات السابقة ظاهرة مع تحذير وتُعطل الإجراءات؛ مهلة القراءة ١٠ ثوانٍ والإجراء ١٥ ثانية.
- رقم الطلب محفوظ في جلسة المتصفح للإعادة بعد نتيجة شبكة غير مؤكدة؛ المعاملة تحفظ النتيجة لمنع التكرار. يمنع قفل واجهة فوري الضغط المزدوج قبل إعادة رسم الزر.
- نموذج الإنتاج يعاد تهيئته عند تغيير الساعة أو حالتها حتى لا تنتقل كميات ساعة إلى أخرى.
- المستند `orderId--slotId--production-v1` ثابت. الـQR يفتح رابطًا ولا يسجل حركة، ومطابقة رقم المستند تتم مع بيانات الساعة الحالية. رابط المختبر `localhost` لا يعمل من هاتف آخر؛ لم يتم فتح قاعدة البيانات للشبكة لتجاوز ذلك.
- استخدمت مكونات الإدخال والأزرار الحالية و`FactoryPrintShell` ومحرك الطباعة المركزي و`qrcode.react` الموجودة بالفعل؛ لا مكتبات إنتاج جديدة.
- بناء الساعات يعيد استخدام المولد الحالي، ويوزع الكمية المطلوبة على الزمن المتاح مع مطابقة الإجمالي حتى عند الكسور والراحة وتعدد الأيام.

## التشغيل والحسابات التجريبية

عند بدء مختبر جديد:

```sh
npm --prefix functions run build
npx firebase-tools emulators:start --project demo-production-line-lab --only auth,firestore,functions
```

في طرفية أخرى، استخدم `npm run seed:lab` مرة لتجهيز الأساس. **الأمر القديم يعيد تهيئة المثال `lab-hourly-order`، فلا تستخدمه لإعادة تعبئة مختبر فيه تجربة تريد الاحتفاظ بها.** ثم:

```sh
npm run seed:lab:roles
npm run dev:lab -- --port 3010
```

`seed:lab:roles` لا يغير أوامر الشغل، لكنه يضبط حسابات وأدوار الاختبار وعماله وخطه المخصصين؛ يرفض أي مشروع أو مضيف غير المختبر المحدد.

| الدور | البريد |
|---|---|
| مدير الإنتاج | production-manager@forgeops.local |
| مشرف الإنتاج | production-supervisor@forgeops.local |
| مدير الجودة | quality-manager@forgeops.local |
| مراقب ١ | quality-inspector-1@forgeops.local |
| مراقب ٢ | quality-inspector-2@forgeops.local |
| مشرف التغليف | packaging-supervisor@forgeops.local |

كلمة المرور التجريبية للجميع: `Lab123456!`. هذه حسابات Auth Emulator فقط. صفحة الدخول: `http://localhost:3010/t/lab/login`.

## دليل الاختبار

رحلة الاختبار: **لوحة المدير → إنشاء واعتماد → callable ومعاملة Firestore → لوحة المشرف → ربط عاملين وتشغيل وتسجيل → بطاقة QR → لوحة المراقب والرابط نفسه**.

| الحد | النتيجة |
|---|---|
| واجهة المدير → الخادم | إنشاء `LAB-CYCLE-002` لكمية ١٠٠ على يومين، ٤ ساعات × ٢٥، ثم اعتماد مستقل عبر حساب المدير |
| الخادم → لوحة المشرف | ظهر الأمر للمشرف المكلف، وفتح رابط المهمة الساعة الأولى |
| العمالة والإنتاج | عاملان بالهوية والاسم، إنتاج ٢٥ ومرفوض مبدئي ٢ وملاحظة محفوظة؛ المقبول المعتمد ظل صفرًا |
| توزيع الجودة | مدير الجودة كلف مراقبين؛ حساب المراقب الأول رأى الحاوية وفتح رابط مستندها، دون أزرار تشغيل أو اعتماد |
| QR | تم فك الرسم فعليًا باستخدام `BarcodeDetector` في المتصفح؛ أعاد رابط الأمر والساعة و`production-v1` الصحيح |
| الطباعة | تمت معاينة البطاقة واستدعاء محرك الطباعة من الزر؛ لا ادعاء باختبار طابعة فعلية أو مسح ورقة مطبوعة |
| فشل الاتصال | offline أظهر تحذيرًا وعطل الإجراءات؛ online أعاد التحميل؛ لا زيادة في الكمية نتيجة فتح البطاقة |
| قواعد الصلاحيات والتزامن | اختبار المعاملات يشمل رفض خارج الشركة/التكليف، تشغيل واحد عند التزامن، تكرار الطلب، توقف واستئناف، وبدء يوم لاحق رغم انتظار الجودة |

اختبارات الكود: `npm run typecheck`، بناء/typecheck الخادم، `npm run build`، `arch:check:legacy-imports`، `tests/work-order-cycle-ui.test.ts`، و`tests/work-order-cycle.integration.ts` عبر emulator نجحت. اختبار `arch:check:theme-tokens` ما زال يفشل بسبب ألوان في `ProductionGateAnalytics.tsx` و`PrintEngineDocumentPreview.tsx` خارج نطاق هذه الدفعة، ولم تُعدل تلك الملفات.

راجعت وفق قائمة React: المكونات الفرعية خارج دوال العرض، تنظيف المؤقتات والأحداث وإهمال الاستجابات المتأخرة، عزل حالة نموذج الساعة، مفاتيح العناصر، labels للأدوات، تعطيل الإجراءات أثناء الحفظ والفشل، وطلبات مستقلة متوازية حيث يمكن. تعديل تنسيق البطاقة للموبايل جاء من مراجعة مرئية فعلية.

### المراجعة البصرية

راجعت RTL على موبايل ٣٩٠، تابلت ٧٦٨، لابتوب ١٣٦٦، وسطح مكتب ١٤٤٠. لم يظهر تجاوز أفقي في القياسات التي فُحصت. تم إصلاح تضييق نص البطاقة على الموبايل بوضع QR أسفل النص؛ كُبّر إلى ١٩٢ بكسل لتحسين وضوح وحداته.

أُصلحت طبقة تنبيه المختبر أيضًا لتبقى تحت طبقة النوافذ الحوارية المعتمدة؛ كانت تخفي زر متابعة نافذة الترحيب على الموبايل. التنبيه نفسه لا يزال ظاهرًا فوق الصفحة العادية ولا يتغير في بناء الإنتاج.

الصور في `docs/qa/work-order-cycle-batch2/`: `mobile-qr.png` و`mobile-create.png` و`tablet.png` و`laptop.png` و`desktop.png`.

ظهرت أثناء التطوير حالة تعليق بعد HMR مع تحذير تحديث حالة من `App` خلال الرسم. إعادة تحميل كاملة أعادت الرحلة للعمل؛ لا نعتبر ذلك إصلاحًا عامًا لمشكلة HMR. لا يُشترط إعادة تحميل بين الإجراءات العادية.

## حدود لم تتحول إلى وعود إنجاز

- تفاصيل تقرير الجودة ما زالت تحتاج اتفاقًا قبل الدفعة الثالثة؛ لا فحص فعلي ولا اعتماد جودة أو تغليف أو مخزون جديد في هذه الدفعة.
- تعديل المسودة وخطتها ذريًا، إعادة إسناد المشرف بسبب، وربط سجل الدورة بواجهة سجل الإجراءات العامة ما زالت بنود استكمال للأساس، وليست منفذة ضمن هذا التسليم.
- القراءة الحالية محدودة لأول ١٠٠ أمر وتصرح بعدم اكتمال القائمة عند تجاوزها؛ الأدلة محدودة بـ٥٠٠ خيار. البحث والتقسيم حسب نطاق المراقب يلزمان قبل تشغيل مصنع كبير، وليس هذا قبول أداء إنتاجيًا.
- ربط العمالة الحالي يحفظ roster الأمر/الخط ولقطة الساعة؛ لا يعيد كتابة سجلات الحضور أو التكليفات اليومية القديمة ولا يرحّل أجورًا.
- تصحيح إنتاج سبق تسجيله أو مستند معتمد لا يتم بتعديل مباشر؛ واجهة التصحيح المؤرخة مؤجلة حسب الخطة.
- المراجعة هنا عربية RTL، وليست قبولًا لـLTR أو طابعة فعلية أو كاميرا هاتف أو اختبارًا شاملًا لكل التطبيق.
- المحاكيات المستخدمة Auth/Firestore/Functions فقط؛ Storage غير مستخدم في مسار هذه الدفعة.
- الأوامر القديمة لم تُرحّل. وفق [قرار تعايش الدورتين](ADR-014-work-order-cycle-v2-foundation.md)، نفس الخط يقبل أوامر قديمة وجديدة، والدورة على مستوى الأمر لا الخط. اختلاف بوابات التشغيل الحالية فجوة تكامل تُعالج وتُختبر قبل النقل، وليس مبررًا لتخصيص خطوط لكل دورة؛ قواعد التزامن مستقلة عن هذا القرار.
